## Confirmed issues and fixes

| Area | Reproduced behavior | Result after the fix |
| --- | --- | --- |
| Request limits | Failed password changes rolled back their attempt counters, so the eleventh attempt was still accepted. | Attempts commit independently of the business transaction; excess attempts return localized HTTP 429 with `Retry-After`. Invalid action arguments also consume the applicable limit. |
| Reception cancellation | An administrator could cancel a checked-in stay without recording checkout, releasing an occupied bed. | Active checked-in stays require reception checkout; cancellation/no-show cannot release them. |
| Physical bed assignment | Moving an already checked-in guest could assign a bed whose previous guest had missed their scheduled checkout and was still physically present. | Assignment and check-in share an actual-occupancy check, including overdue stays loaded by the existing indexed query. |
| Inventory edits | Capacity could be reduced below the combined total of confirmed reservations and maintenance blocks. | Capacity validation includes the peak combined commitments; valid reductions after cancellation remain possible. |
| Internal finance privacy | Public property data included commission rules. Retrying an existing booking returned staff identifiers and internal finance history in the action payload, although the state payload filtered them. | Guests receive no property commission rule; action booking payloads reuse the same redacted state representation. Admins retain access. |
| Coupon privacy | Anonymous visitors could download every coupon code, including inactive and expired promotions. | Only admins receive the coupon list. Guests validate a known code through `checkCoupon`; the booking form retains that specific validation result and booking submission still checks validity/usage on the server. |

Six new API integration tests reproduce these issues, including failed-write
rollback, post-limit recovery, checkout recovery, and guest/admin visibility.
The five original cases failed before the fixes; the coupon case was also run
and failed before its fix. The browser workflow now exercises applying,
removing, reapplying and redeeming a known code with an empty public coupon list.
